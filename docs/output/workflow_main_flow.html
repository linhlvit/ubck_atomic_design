Tiêu chí Self-Review theo từng Phase
📐 HLD · Phase 1 — Checklist tự kiểm tra trước khi xuất HLD.md
Section 1 — Data Lineage
□Mỗi Cụm tổ chức theo 1 Fact duy nhất
□Mỗi flowchart đủ 3 subgraph: SRC / SIL / GOLD
□Cụm có Fact phải có ECAT.ECAT_29_HolidayInfo + Calendar Date Dimension
□Node Staging: ID không có dấu chấm
□Dim xuất hiện trong GOLD; edge Dim → Fact (không phải ngược)
□BẮT BUỘC Mọi Dim trong GOLD có ít nhất 1 Atomic entity nguồn trong SIL với edge đầy đủ
□Mọi Atomic entity dùng ETL join vào Fact phải có edge riêng vào Fact
□Node label trong flowchart không dùng \n
Section 2 — Tổng quan báo cáo
□Hierarchy đúng: ### Tab → #### Nhóm {STT} - tên → ##### READY/PENDING (chỉ khi có cả 2)
□Tên Tab = phần TRƯỚC dấu /; Nhóm = STT gốc từ BA + phần SAU /
□BẮT BUỘC Bảng KPI READY chỉ có 1 bảng duy nhất — không tách KPI mới / KPI reuse
□Mọi dòng BA Phân loại = Chiều có KPI_ID — không được bỏ qua
□Không dùng shorthand "xem Nhóm N" — liệt kê explicit từng KPI_ID
□Lineage Mart → Báo cáo: node bắt đầu là Fact/Dim/Operational GOLD — không vẽ Atomic
□Block PENDING: chỉ 4 cột (KPI ID/Tên/Tính chất/Trạng thái) — không có Đơn vị, Công thức
□Block PENDING không có Star Schema, erDiagram, Lineage
□Tên attribute trong cột Nguồn = attribute.name từ YAML (không tự đặt)
□Dedup KPI cross-nhóm: trùng nội dung → reuse ID cũ, không cấp ID mới
□Đồng bộ "KPI liên quan" trong PENDING header với bảng KPI bên dưới
Section 3 + 4 + erDiagram
□Section 3 không bao gồm bảng PENDING
□Bảng Phân tích: chỉ liệt kê Fact (không liệt kê Dim)
□Bảng Dimension: ghi chú "Tất cả áp dụng SCD Type 4A"
□Section 4: mỗi bảng trong Sec 3 có 1 dòng; reuse_status đã human xác nhận
□erDiagram mở bằng ```mermaid (không phải ```erDiagram)
□Types chỉ dùng: int/float/string/varchar/boolean/date/datetime
□Chỉ dùng label PK và FK — không có NK/BK/DD trong erDiagram
□BẮT BUỘC Scan toàn file: không có Population_Date / Effective_Date / Expiry_Date / Snapshot_Date
□Số trường + tên trường đồng nhất ở mọi erDiagram trong file
□Chỉ dùng tên logical — không có snake_case ở bất kỳ đâu
📐 HLD · Phase 2 — Checklist Entities Files
□Danh sách entity đầy đủ từ Section 3 (fact + dim + operational)
□table_type khớp phân loại Section 3 (fact/dim/operational)
□reuse_status lấy từ Section 4 — không tự suy luận
□source_table tra từ dm_manifest.yaml (physical_name) — không đoán
□FKs: chỉ điền cho fact; trống cho dim/operational
□FKs trích từ graph TB Section 3, format {Dim Entity}.{Dim Entity Id}
□status = draft toàn bộ rows
□Thứ tự: Dimension → Fact → Operational
□Export UTF-8 BOM (utf-8-sig)
□Entities.md: erDiagram chỉ vẽ relationship lines — không vẽ attribute block

🔧 LLD · Phase 1 — Checklist nội dung Attributes CSV (kiểm tra trước khi submit từng file)
Key & Nullable
□nullable = false cho PK / BK / NK / FK
□Cột từ LEFT JOIN → nullable = true
□data_domain = Classification Value → key trống
□data_domain = Surrogate Dimension Key → key = FK → <Dim>
□data_domain = Surrogate Key không xuất hiện trên Fact
□Operational: trường _code làm PK duy nhất — không tạo surrogate _id
□Mọi Dimension có ≥ 1 NK
etl_logic_type
□direct: chỉ khi atomic_table = driving table
□computed: chỉ khi TẤT CẢ input từ driving table (kể cả EXISTS, CASE WHEN)
□join_atomic: atomic_table KHÁC driving — ghi rõ INNER/LEFT JOIN
□lookup_date: FK → Calendar Date Dimension
□lookup_dim: FK → SCD4A Dim qua NK
□pivot: số branch + thứ tự đồng nhất; branch residual flatten về Atomic
□pending: etl_logic để trống; không dùng cho row đã READY
□Không dùng etl_logic_type = "framework"
src_stm_code (dim & operational)
□Mọi bảng dim/operational có attribute src_stm_code cuối danh sách
□Single-source: luôn có WHERE src_stm_code = 'value' (forward-compatibility)
□Multi-source cùng lúc: WHERE src_stm_code IN ('v1','v2',...)
□Multi-source tách bộ: N bộ × M dòng, mỗi bộ có src_stm_code riêng
□Fact "No Driving Table": không thêm src_stm_code
□Bộ chưa xác định Atomic → etl_logic_type = pending toàn bộ bộ
Mapping & Naming
□Mọi mapping tra từ entity YAML — không đoán atomic_column
□Join key giữa Atomic: ưu tiên surrogate key (_id) thay vì business code
□Driving Table ghi rõ trong description của PK/BK
□Multi-hop: source_entity/table/attribute/column phản ánh bảng CUỐI chain
□ETL runtime: dùng {etl_date} — không dùng tên biến tùy ý
□Không thiết kế Effective/Expiry/Population Date
□Export UTF-8 BOM (utf-8-sig)
□etl_logic có dấu phẩy → đã double-quote trong CSV

🔧 LLD · Phase 3 — Post-Check Flat Table SQL
File 01 — CREATE TABLE
□Số bảng = số fact + số operational
□Naming fact: {module}_{datamart_table}_flat
□Naming operational: {datamart_table}_flat (không có module prefix)
□Thứ tự cột: fact cols → Calendar Date 9 cols → dim cols → technical metadata
□Operational: chỉ operational cols → technical (không có Calendar Date, không có dim)
□Calendar Date: đúng 9 cột cố định
□Dim cols: bỏ PK surrogate + src_stm_code; giữ giá trị nghiệp vụ; COMMENT ghi "— từ {Dim Name}"
□Data type dùng ClickHouse types (Nullable wrapper theo nullable)
□ENGINE = ReplicatedReplacingMergeTree()
□PARTITION BY toYYYYMM(<cột DD>); ORDER BY (<cột DD>, <grain_key>)
File 02 — POPULATE (INSERT)
□Số TRUNCATE + INSERT = số bảng trong file 01
□SELECT list đủ cột, đúng thứ tự khớp CREATE TABLE
□Đếm cột SELECT = đếm cột CREATE (kể cả ds_batch_date, ds_population_timestamp)
□Nguồn fact: {module}_{datamart_table} (có prefix module)
□Nguồn operational: {datamart_table} (không prefix)
□Calendar Date join: {module}_calendar_date_dimension
□Dim join: alias rõ ràng, ON {dim_pk} = f.{fk_col}
□today() AS ds_batch_date; now() AS ds_population_timestamp
□Operational: không có LEFT JOIN
Cross-Check tổng thể
□Mỗi cột trong CREATE có đúng 1 entry tương ứng trong SELECT
□Không có cột nào trong Attributes.csv bị bỏ sót trong CREATE TABLE
